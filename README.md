# Shinny Master — Шиномонтаж, хранение, ремонт дисков

Full-stack приложение для автосервиса: управление заказами, запись, склад шин, чат, отчёты.

## Стек

- **Next.js 16** (App Router) + TypeScript 5
- **Prisma 6** + PostgreSQL
- **Auth.js** (NextAuth v5) — JWT-аутентификация
- **Socket.IO** — real-time чат и обновления
- **Tailwind CSS v4** + Shadcn UI / Base UI
- **FSD архитектура** (`src/app/`, `features/`, `entities/`, `shared/`, `widgets/`)

---

## Реализованный функционал

### Авторизация и роли

- Регистрация клиентов (`/auth/register`) — имя, email, телефон, пароль
- **Согласие на обработку персональных данных** (152-ФЗ) — обязательный чекбокс при регистрации
- Вход (`/auth/login`) — email + пароль, JWT-сессия
- Seed-страница (`/auth/seed`) — создание первого владельца системы
- 3 роли: **Owner**, **Master**, **Client** — с разными правами доступа
- Middleware с защитой маршрутов

### Дашборд (`/dashboard`)

- Server Component с Prisma-запросами
- Статистика по ролям: заказы, активные, завершённые, мастера, клиенты

### Заказы (`/orders`)

- Список заказов с фильтрацией по ролям
- **Пагинация** — серверная, 20 заказов на страницу, навигация с эллипсисом
- Создание заказа через диалог (клиент)
- Карточка заказа (`OrderCard`) — статус, тип услуги, авто, размер шин, телефон, дата визита, фото
- Этапы ремонта (`RepairProgress`) — визуальный прогресс-бар с этапами по типу услуги
- Действия мастера (`MasterActions`) — "Далее" (переход к следующему этапу), "Отменить"
- Редактирование заказа (`EditOrderDialog`) — для клиента на статусе Pending
- Загрузка фото — мастер может прикреплять фото к заказу, просмотр в галерее
- Удаление заказов — с подтверждением
- Real-time обновления через Socket.IO (`order-stage-refreshed`, `order-removed`)

### Бронирование (`/booking`)

- 4-шаговый мастер: Мастер → Дата (календарь) → Время (слоты) → Детали заказа
- Выбор типа услуги (шиномонтаж, хранение, ремонт дисков, балансировка и др.)
- Автоматическое создание заказа + слота расписания

### Чат (`/chat`)

- Диалоги со списком контактов и превью последнего сообщения
- Real-time переписка через Socket.IO
- Отправка сообщений с текстом + вложения
- Emoji-picker (emoji-picker-react)
- Загрузка файлов — изображения, PDF, документы, архивы
- Просмотр вложений — галерея изображений, iframe для PDF/документов
- Онлайн-статус пользователей
- Прочтение сообщений (автоматическое)
- Удаление сообщений — свои + Owner может удалить любые
- Удаление диалогов — целого диалога или конкретного
- Очистка диалогов (Owner) — диалоги мастеров / все диалоги
- Экспорт чата (Owner) — TXT, Excel, PDF
- Поиск пользователей для нового диалога
- Привязка диалога к заказу

### Панель мастера (`/master`)

- Список своих заказов с табами: Активные / Завершённые / Отменённые
- Real-time обновление через Socket.IO
- Периодический polling каждые 10 секунд

### Расписание мастера (`/master/schedule`)

- Настройка рабочих часов по дням недели

### Хранение шин (`/tires`)

- Список шин с поиском и фильтрацией (статус: на хранении / выданы)
- Принятие шин — мастер/владелец могут принять шины на хранение
- Выдача шин — смена статуса на "Выданы"
- Информация: бренд, модель, размер, сезон, количество, место на стеллаже

### Админка (`/admin`)

- Управление пользователями — таблица с аватарами, ролями, датами
- CRUD пользователей: создание (с копированием учётных данных), редактирование, удаление
- Смена ролей (Master ↔ Client)
- Уведомления (`/admin/notifications`)

### Список пользователей (`/users`)

- Карточки пользователей с аватаром, ролью, email, телефоном
- Количество заказов и дата регистрации
- Поиск по имени / email / телефону
- Фильтр по роли (Клиенты / Мастера / Владельцы)
- Пагинация (20 на страницу)
- Доступ: Master и Owner

### Политика конфиденциальности (`/privacy`)

- Политика обработки персональных данных по 152-ФЗ
- 9 разделов: общие положения, собираемые данные, цели, правовые основания, сроки, права субъекта, меры защиты, изменения, контакты
- Публичный доступ (без авторизации)

### Настройки (`/settings`)

- Название компании, адрес, телефон
- График работы по дням недели (вкл/выкл + время начала/конца)

### Аккаунт (`/account`)

- Просмотр и редактирование профиля
- Загрузка аватара (с кропом через react-easy-crop)
- Смена пароля
- Удаление аккаунта
- Статистика по роли

### Отчёты (`/reports`)

- Заказы по статусам
- Заказы по мастерам
- Заказы по месяцам
- Активность клиентов (среднее заказов на клиента)

### Оплата СБП (real-time)

- Мастер завершает заказ → вводит сумму в диалоге «Стоимость работ»
- Автоматическое создание платежа СБП (mock QR-ссылка `https://qr.nspk.ru/...`)
- **Клиент получает QR-код в реальном времени** через Socket.IO (`payment-created`)
- Кнопка «Оплата СБП» на карточке завершённого заказа (Master/Owner)
- Копирование ссылки для ручной отправки клиенту
- Подтверждение оплаты мастером/владельцем
- Статус: pending → paid / cancelled
- Запись `paidAt` в заказе после подтверждения
- Цены услуг предзаданы (от 500 до 2 000 ₽) и подставляются при создании заказа

### Тема

- Тёмная/светлая тема (ThemeToggle в хедере, localStorage persistence)

### API-эндпоинты

`auth`, `admin/users`, `orders`, `orders/[id]`, `orders/[id]/photos`, `orders/appointments`, `chat/dialogs`, `chat/messages`, `chat/upload`, `chat/export`, `chat/online`, `tires`, `schedule/slots`, `schedule/hours`, `settings`, `users`, `users/masters`, `users/search`, `notifications`, `account`, `auth/seed`, `payments`, `payments/[id]`

### Socket.IO события

`order-stage-updated`, `order-removed`, `order-deleted`, `payment-created`, `new-message`, `dialog-removed`, `dialogs-refresh`, `dialogs-cleared`, `send-message`, `typing`

### Shadcn UI компоненты

button, card, dialog, sheet, badge, select, calendar, popover, tooltip, separator, scroll-area, confirm-dialog, sonner (toast), **pagination**

## Деплой на Vercel

### 1. Создай удалённую PostgreSQL (Neon)

1. Зарегистрируйся на [neon.tech](https://neon.tech) (бесплатно, без банковской карты)
2. Создай новый проект:
   - Название: любое (например `shinny-master`)
   - Регион: ближайший (Europe-West)
3. В панели Neon скопируй **Pooled connection string** — он выглядит так:
   ```
   postgresql://neondb_owner:xxxx@ep-xxx.us-east-2.aws.neon.tech/shinny_master?sslmode=require
   ```
4. Выполни миграцию на новую БД:
   ```bash
   cmd /c "npx prisma db push"
   ```

### 2. Установи Vercel CLI

```bash
cmd /c "npm install -g vercel"
```

### 3. Разверни проект

```bash
cmd /c "vercel"
```

Следуй инструкциям в терминале:
- Логин через браузер (создай аккаунт если нет)
- **Link to existing project?** → No
- **Project name** → shinny-master (или любое)
- **Directory** → `./` (текущая)

### 4. Настрой переменные окружения

В панели Vercel (vercel.com → проект → Settings → Environment Variables) добавь:

| Переменная | Значение |
|------------|----------|
| `DATABASE_URL` | Строка подключения из Neon |
| `AUTH_SECRET` | `2f183de4154622e288ff6eb0943441fe3c039b48ddbadb04320eca331d08d9b6` |
| `NEXTAUTH_URL` | URL твоего проекта на Vercel (например `https://shinny-master.vercel.app`) |
| `SEED_SECRET` | Секретный ключ для создания владельца (произвольная строка) |

### 5. Деплой в продакшн

```bash
cmd /c "vercel --prod"
```

### 6. Создай первого владельца

Открой `https://твой-проект.vercel.app/auth/seed?secret=ТВОЙ_SEED_SECRET` и создай аккаунт владельца.

> **Логика seed:** Одноразовый процесс. API проверяет `SEED_SECRET` из `.env` и что в базе нет пользователей. После создания владелец автоматически логинится. Повторное создание невозможно — `count(users) > 0` блокирует запрос.

## Тестирование оплаты СБП

### 1. Подготовка

```bash
# Останови dev-сервер, затем:
cmd /c "npx prisma generate"
cmd /c "npm run dev"
```

### 2. Создай заказ

Клиент создаёт заказ через `/booking` (выбрав услугу — цена подставится автоматически) или `/orders` (кнопка «Новый заказ»).

### 3. Мастер завершает заказ

На панели мастера (`/master`) нажимай «Далее», пока не дойдёшь до последнего этапа. Кнопка сменится на **«Завершить»**.

### 4. Введи сумму

При нажатии «Завершить» откроется диалог **«Стоимость работ»**. Введи сумму в ₽ и нажми «Завершить».

### 5. Клиент получает QR-код

Клиент видит уведомление и QR-код СБП **в реальном времени** (Socket.IO). Открывается диалог оплаты с суммой и QR-кодом.

### 6. Подтверди оплату

Мастер/владелец нажимает **«Подтвердить»** на карточке заказа — статус меняется на «Оплачено».

### 7. Проверь в Prisma Studio

```bash
cmd /c "npx prisma studio"
```

Таблица `payments` — платёж со статусом `paid` и заполненным `paidAt`.
